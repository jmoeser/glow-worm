# Transaction balances

Read this before changing how a transaction updates `SinkingFund.current_balance`, `Budget.fund_balance`, or `Budget.spent_amount`. `AGENTS.md` only points here. This service is the only place those balances are applied. Overspend transfers and the budget overdraft warning are in `docs/budgets.md`.

## Transaction balances

`app/services/transaction_balances.py` is the only place that applies a transaction to `SinkingFund.current_balance`, `Budget.fund_balance`, and `Budget.spent_amount`. The transactions HTML routes, the JSON API, and the MCP transaction tools all use it. The dashboard quick-expense form calls the same spent helper. `type` `income` or `transfer` adds the amount to the linked fund; any other `type` subtracts. `is_paid` and `transaction_type` do not change the sinking-fund balance. `budget_transfer` adds the amount to `Budget.fund_balance`; that effect is reversed on delete and when the amount, transaction type, budget, or fund link changes. `spent_amount` changes only for an expense whose `transaction_type` is `budget_expense` and whose `budget_id` is set (the same rows quick-expense creates). The amount is added on create, subtracted on delete, and on edit the net change is applied once: amount edits, a move between budgets, clearing or setting `budget_id`, and a type or classification change that starts or stops counting. Income and contribution refunds do not change `spent_amount`. The value is quantized to 0.01 and clamped at 0, including negative zero, because the column is non-negative. An edit on the same budget clamps after the net change, so it does not bounce off zero and then add the new amount. `fund_balance` is not affected by spent tracking. Update reverses the previous fund snapshot, then applies the new one, including a move between funds and to or from no fund.
