# Transaction balances

Read this before changing how a transaction updates `SinkingFund.current_balance`, `Budget.fund_balance`, or `Budget.spent_amount`. `AGENTS.md` only points here. Income allocation still assigns `current_balance` outside this service. Overspend transfers and the budget overdraft warning are in `docs/budgets.md`.

## Transaction balances

`app/services/transaction_balances.py` applies a transaction to `SinkingFund.current_balance`, `Budget.fund_balance`, and `Budget.spent_amount`. Bill auto-pay and manual pay use it too. Income allocation, the income page, and secondary-income distribution still assign `current_balance` directly. The transactions HTML routes, the JSON API, and the MCP transaction tools all use the helper. The dashboard quick-expense form calls the same spent helper. One-off fund expenses use the helper and are not occurrence rows. The sinking-fund write is one `UPDATE` of `current_balance = current_balance + delta` (the delta quantized to cents), then `current_balance` is expired on any loaded fund. `spent_amount` stays read-modify-write, including the clamp at zero. Two overlapping budget confirms of different bills on the same category can still drop one spent update. The helper is not race-free. `type` `income` or `transfer` adds the amount to the linked fund; any other `type` subtracts. `is_paid` and `transaction_type` do not change the sinking-fund balance. `budget_transfer` adds the amount to `Budget.fund_balance`; that effect is reversed on delete and when the amount, transaction type, budget, or fund link changes. `spent_amount` changes only for an expense whose `transaction_type` is `budget_expense` and whose `budget_id` is set (the same rows quick-expense creates). The amount is added on create, subtracted on delete, and on edit the net change is applied once: amount edits, a move between budgets, clearing or setting `budget_id`, and a type or classification change that starts or stops counting. Income and contribution refunds do not change `spent_amount`. The value is quantized to 0.01 and clamped at 0, including negative zero, because the column is non-negative. An edit on the same budget clamps after the net change, so it does not bounce off zero and then add the new amount. `fund_balance` is not affected by spent tracking. Update reverses the previous fund snapshot, then applies the new one, including a move between funds and to or from no fund.
